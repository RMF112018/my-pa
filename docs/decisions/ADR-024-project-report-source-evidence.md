## Context

The operator saves reports in Procore (meeting items, observations, coordination issues, RFIs, budget changes, buyout, change-order reconciliation, daily log) and exports them as CSV into one folder per project. The inventory of 2026-11-21 holds 20 files from 3 projects, 15 distinct header signatures, about 360 KB. The exports group rows one or two levels deep and print subtotals and a `Grand Totals` row; some exports are header-only or grouping-only; some cells are multi-line; money is printed with currency symbols and separators. Saved-report filters are invisible in the file.

[ADR-022](ADR-022-communications-intelligence.md) decision 2 already named PULSE as the second consumer of the shared ingestion lifecycle and left its storage undesigned. [ADR-018](ADR-018-financial-controlled-source-model.md) (the controlled financial source model) is Proposed, not accepted; open decision OD-06 (which real financial source is authoritative) is unresolved. The Manager rulings D1–D19 on the WP3P investigation (2026-11-24) settle the design; this ADR records them as built.

## Decision

1. **Read-only original-source evidence.** PULSE exports are original-source evidence (`AGENTS.md` section 4): my-pa reads them through the read-only workspace store and never writes, renames or trashes them, and never calls Procore. They are not product-owned records ([ADR-003](ADR-003-product-owned-user-authored-source-records.md)), not report-plane artifacts ([ADR-010](ADR-010-intelligence-artifact-report-plane.md)) and not managed documents.
2. **PULSE money is source evidence, not the controlled financial source (D13).** The financial families (budget changes, buyout, change-order reconciliation) are persisted as read-only source evidence, in `NUMERIC(20,4)`. They are not the ADR-018 controlled financial source: no ledger, no revised contract, no EAC, no certified totals, no `programs.financial`. ADR-018 and its import guard are unchanged, and OD-06 stays open. No financial value is written to any product-owned record. Nothing is authored, posted or reconciled into an authoritative ledger, so this is not a risk acceptance under `AGENTS.md` section 8.2; it is listed for operator visibility.
3. **The second consumer of the shared lifecycle (ADR-022 decision 2).** The consumer `pulse_csv_export` uses the existing `ingest_sources`, `ingest_snapshots`, `ingest_snapshot_paths`, `ingest_runs` and `ingest_run_snapshots` rows; no lifecycle table, status or vocabulary is added. The lifecycle gains three consumer-neutral additions and nothing else: `IngestionLifecycle.admit_within` (admission inside the caller's unit of work, never committing; `admit` is now its own transaction around it, with the same refusals in the same order), the read-only property `IngestionLifecycle.consumers` (the consumers it holds a handler for; the bindings service raises at construction over a lifecycle without `pulse_csv_export`), and the repository read `IngestionRepository.list_paths_of_snapshot` (every path row of one snapshot, superseded or not, ordered by first-seen instant then path). Series membership and aliases are derived at read time from the snapshot's path rows and its header signature (D4).
4. **Its own lifecycle instance, step, switch and lock (D5).** A second `IngestionLifecycle` holds exactly one handler, the project-reports handler; the communications lifecycle never holds it, so the generic communications `admit` refuses `pulse_csv_export` (`consumer_not_registered`) and a project-report source is admitted only by `bindings apply`. The cycles plane runs it as its own step `project_reports_ingest` under `MY_PA_PROJECT_REPORTS_INGEST_ENABLED` (default off) every `MY_PA_PROJECT_REPORTS_INGEST_POLL_SECONDS` (default 900, 60–86,400), under its own advisory lock `PROJECT_REPORTS_POLL_LOCK_KEY` (`advisory_lock_key(b"my-pa-project-reports-poll")`). The plane now has three switches; any one of them starts it, and with all three off it exits 2. The read switch arrives with WP4P.
5. **Quarantine is consumer-level (D3).** A rejected file is a lifecycle `rejected` snapshot (`not_utf8`, `malformed_csv`, `invalid_header`, `nul_byte`). An unknown header signature, a malformed-row ratio above 1 %, or a project-number mismatch against the binding (D11) is a lifecycle `ingested` snapshot whose derivation is `quarantined` with that reason: every raw row is kept, no row is classified or typed.
6. **Layer A keeps the raw rows: a measured exception to ADR-022 decision 10.** `project_report_snapshots` and `project_report_rows` hold the byte-exact header and every raw record (text, terminator, cells), classification-free. The handler re-reads the stored rows and hashes their reconstruction; the database requires `reconstruction_sha256` to equal the lifecycle's `file_sha256` through a composite foreign key. Communications keep "no raw content in PostgreSQL"; PULSE rows are small, structured, needed for reconstruction and for re-derivation without the file. The free-text columns are inventoried by a guard, nothing logs them, and no capability reads them in this package.
7. **Classification and typing are append-only, rebuildable derivations (D1, D2, D9, D10).** A derivation (`prdrv_`) is written from the stored Layer A rows under one adapter version and one binding revision, and holds the row roles, generic lines with typed values over a closed per-family field catalogue, and the stated totals with their reconciliation. A derivation is superseded at most once, only by a later derivation of the same snapshot, so each snapshot's chain is linear and acyclic and exactly one derivation is current. "Current" is the one nothing supersedes; there is no mutable `latest_*` column, and the view `project_report_current_derivations` is the reader's only route. A bounded sweep after each poll re-derives automatically when a quarantined signature gains an adapter, a binding is corrected, or an adapter, identity or status-map version changes; the operator can force a rebuild (`rederive`).
8. **Header-signature registry as code.** The 15 known signatures and their adapters live in `infrastructure/project_reports/pulse_csv.py`, the only module that holds a Procore header string. An unknown signature quarantines with rows kept and is picked up by the sweep, with no operator action, once its adapter ships in a PR.
9. **Measures are safe by construction.** Sums are over detail rows only; approved, pending, void and unknown are kept apart; money is `Decimal`, more than 4 decimals is refused (`more_than_4_decimals`, never rounded), and no module uses `float`; a stated total is compared with its recomputed detail sum (`match`, `mismatch`, `both_empty`, `not_checked`). A PULSE-local money parser with a parity test is used, so the ADR-018 import guard stays unchanged.
10. **Record identity per family, versioned (`prrec_`).** Identities are keyed by Project, family, identity key and identity version. Closure is never inferred from disappearance: a record missing from a later version is `not_observed_in_latest`.
11. **The crosswalk is operator runtime data (D6, D7, D8, D12, D19).** The operator's bindings file (`my_pa_project_report_bindings_v1`) is the whole desired state of one workspace and is never committed. `bindings apply` validates it fail-closed (one closed refusal code, nothing written), then admits, binds and enables in one transaction under the poll lock. A folder omitted from a later file is retired: its source is disabled and every row stays. Binding revisions (`prbnd_`) are append-only; each supersedes at most one earlier revision of the same source, so each source's chain is linear and acyclic and its pointer only moves forward. The revisions are the audit (`recorded_by = operator_cli`); no `audit_events` row is written. A source with no active binding is never ingested or re-derived: `run-once` and `backfill` refuse `source_unbound` up front and write nothing, and the handler's in-transaction `source_unbound` remains as defence in depth.
12. **Filter semantics are `unknown` unless declared (R-OP-5).** An operator filter declaration in the bindings file applies to versions first seen at or after it; nothing is derived from a slug.
13. **Per-Project only.** Every typed row carries its `project_id`; a Program rollup becomes possible only on a verified entity relationship (R-OP-5, WP4P).
14. **Content is inert and never leaves as text.** Refusals, rejection errors, log lines and command output carry closed codes, counts, identifiers, UTC timestamps, ISO dates and project numbers only: never a cell, path, folder, file name, slug or filter description. Rejection diagnostics are code-only in the database; an ordinal or offset appears only in local dry-run or aggregate output (D16).
15. **No new capability, purpose or lineage family.** The package adds no capability, purpose or grant; the operator command is configuration, not a capability. No `Capability`, `Purpose`, `IdKind` or table name carries `pulse` or `procore` (`continuity.pulse` already means something else). PULSE is not admitted to the record-lineage taxonomy ([ADR-015](ADR-015-record-lineage-and-issue-situations.md) decision 6 unchanged).

## Consequences

- Twelve Principal-partitioned tables and one view in `knowledge`, three identifier kinds (`prbnd`, `prrec`, `prdrv`). Eleven tables are append-only; the binding pointer is named-mutable; `TRUNCATE` is refused on all twelve; the downgrade refuses while any row exists.
- The migration takes its locks up front under a 10 s `lock_timeout`, so it aborts cleanly at `61fafdfd2986` rather than deadlocking; it should still be applied with the cycles worker stopped.
- Raw export text (names, descriptions, minutes) sits in PostgreSQL. It is Principal-partitioned, unlogged and unread until WP4P, whose eligibility decision follows R-OP-3.
- Storage grows by about one copy of each export per derivation generation (about 360 KB for the current 20 files); retention is a later operator decision.
- A binding correction leaves earlier derivations in place. Any reader that skips the current-derivation view would double count, so WP4P must read through it.
- Longitudinal behaviour is proven on synthetic versions only until a second real export generation exists.

## Rejected alternatives

| Alternative | Reason rejected |
| --- | --- |
| A PULSE-specific ingestion lifecycle | duplicates snapshot, idempotency and run machinery (ADR-022 decision 2) |
| A lifecycle-level `quarantined` status | restates the WP3a CHECK and finalize-once trigger and touches the communications paths; consumer-level quarantine follows the communications precedent |
| PULSE money as the ADR-018 controlled source | ADR-018 is Proposed and OD-06 is open; the exports are evidence, not a designated ledger |
| One typed table per family | 15 views would need about 19 tables; a generic line plus typed values over a closed catalogue (the ADR-023 decision 6 precedent) needs 2 |
| Mutable `latest_snapshot_id` / `latest_status_class` | arrival order within a run is by SHA-256, so a projection would depend on order; "current" is computed |
| An `audit_events` row per bindings apply | the ingestion unit of work has no audit sink and an operator command is not a capability; the revision rows are the audit |
| Store only typed values, not raw rows | loses byte-exact reconstruction and re-derivation without the file |
| Infer closure or status from a report's slug or from disappearance | the filter is invisible in the file; absence is not closure |
| Register the handler in the communications lifecycle | the generic `admit` could then bypass the bindings |

## Supersession

This ADR supersedes nothing. It extends ADR-022 decision 2 (names and builds its second consumer) and makes a scoped exception to ADR-022 decision 10 for PULSE only. ADR-018, ADR-019 and ADR-015 are unchanged. Changing record identity, adding a client write, a capability or a lineage family, treating PULSE money as a controlled financial source, or adding a lifecycle status needs an amendment or a superseding ADR. A new header signature, adapter or adapter version, field-catalogue entry or count key is a code change under review, not an ADR change.
